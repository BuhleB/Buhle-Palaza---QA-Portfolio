PLAYWRIGHT · TYPESCRIPT

Check the outcome, not just the click

I built this project around SauceDemo user journeys and added browser-interaction checks on The Internet demo. I check product identity, prices, cart state and navigation so a successful click alone cannot make a test pass.

What I cover

  • Valid login, invalid credentials, locked-out users and missing fields.
  • Adding and removing products, cart contents and persistence after refresh.
  • Product details, price sorting, alphabetical sorting and logout.
  • Checkout cancellation, browser alerts and dynamically loaded text.

How I structure the checks

  • Page objects for login, inventory and checkout actions.
  • Role and data-test locators, reusable setup and parameterised inputs.
  • Retrying assertions and polling for changing content.
  • Chromium, Firefox and WebKit configured with one worker.

Example: verify the product added to the cart
test('CART-01: added product appears in cart @smoke', async ({ page }) => {
  const inventory = new InventoryPage(page);

  await inventory.addProduct('Sauce Labs Backpack');

  await expect(page.getByTestId('shopping-cart-badge')).toHaveText('1');

  await inventory.openCart();

  const cartItem = page.getByTestId('inventory-item');

  await expect(cartItem).toHaveCount(1);
  await expect(cartItem.getByTestId('inventory-item-name'))
    .toHaveText('Sauce Labs Backpack');
  await expect(cartItem.getByTestId('inventory-item-price'))
    .toHaveText('$29.99');
});

The configuration retains screenshots, traces and video on failure and generates an HTML report. GitHub Actions installs the browsers, runs the suite and uploads the report.

HOW I APPROACHED IT

My Selenium frameworks

SauceDemo · Java/TestNG

  • Page objects keep locators and actions separate from assertions.
  • Full regression, smoke and cross-browser suites provide different execution scopes.
  • Data-driven login checks cover six demo users.
  • ExtentReports and failure screenshots support investigation.

OrangeHRM · Python/pytest

  • Fixtures manage browser and login setup.
  • Five functions expand to six test cases.
  • Explicit waits synchronize browser interactions.
  • pytest-html includes screenshots for test-call failures when the browser is available.
