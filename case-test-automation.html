HOW I APPROACHED IT

Reusable checks with visible failure evidence

SauceDemo · Java/TestNG

  • Page objects keep locators and actions separate from assertions.
  • Full regression, smoke and cross-browser suites provide different execution scopes.
  • Data-driven login checks cover six demo users.
  • ExtentReports and failure screenshots support investigation.

OrangeHRM · Python/pytest

  • Fixtures manage browser and login setup.
  • Five functions expand to six test cases.
  • Explicit waits synchronize browser interactions.
  • pytest-html includes screenshots for test-call failures when the browser is available.

I reviewed AI-assisted code changes and checked them by running the suites against the demos. The saved results below are the evidence for those runs.

How the test counts expand

The full regression configuration selects 27 methods. Six login data rows replace one method invocation, producing 32 executions. Smoke selects seven methods. Cross-browser runs five methods in each of three browsers. OrangeHRM has five functions, with invalid login parameterized into two cases.

MAINTAINABILITY

What is configured, and what remains to improve

Both suites use explicit waits without fixed sleeps. SauceDemo also configures a five-second implicit wait. Its cross-browser XML runs the selected classes sequentially; this portfolio does not claim parallel cross-browser execution.

A GitHub Actions smoke workflow is configured for SauceDemo. A workflow file demonstrates configuration; a successful hosted CI run needs its own execution record.
