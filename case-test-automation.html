THE PROJECTS

Automation Frameworks and Test Coverage

SauceDemo Framework (Java)

  • Public e-commerce demo, saucedemo.com
  • Java 11 compiler target; Java 17 CI runtime; Selenium, TestNG, Maven
  • Page Object Model; one driver per thread
  • 3 suites: full regression, smoke, cross-browser
  • Headless mode + GitHub Actions smoke workflow

OrangeHRM Suite (Python)

  • Public HR-system demo, opensource-demo.orangehrmlive.com
  • Python, Selenium, pytest, Page Object Model
  • Fixtures for the browser and the logged-in state
  • pytest-html reporting hook attaches screenshots for test-call failures when the browser is available
  • 5 test functions producing 6 cases; leave availability marked xfail
SCOPE

What the suites check

LOGIN

Valid and invalid credentials, locked-out, problem and performance-glitch users, empty fields, repeated failed attempts.

INVENTORY

Product count and details, add and remove items, cart kept after a refresh, sorting by price and name, logout.

CHECKOUT

Full purchase, each required field left empty, several items, cancelling, special characters in the form.

CROSS-CUTTING

Five SauceDemo core journeys on Chrome, Firefox and Edge; six data-driven login rows in the full suite; OrangeHRM login, reset-page navigation and leave-form availability.

AUTOMATION DESIGN

Assertions, synchronization and reporting

Source-aligned suites

TestNG XML files select full regression, smoke and sequential cross-browser classes. Assertions check navigation, error messages, cart counts, sorting and checkout outcomes.

OrangeHRM recovery check

The password-reset check uses a text-based locator and asserts navigation to the reset page. The saved report records a failed link-presence assertion. The current source uses a text-based locator; no later successful retest is established by that report.

Observations and test data

Case-insensitive usernames are recorded as an observation. Leave-form availability uses non-strict xfail. The saved run reached the dropdown-availability assertion and reported XFailed, so the result should not be attributed solely to a missing leave balance. XPASS would indicate a passing check rather than prove a product fix.

Waits and failure evidence

Both suites use explicit waits without fixed sleeps. SauceDemo also configures a 5-second implicit wait. Failure hooks attempt screenshots; the OrangeHRM hook covers test-call failures rather than fixture setup failures.
