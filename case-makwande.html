THE PROBLEM

A careers workflow with no central home

Makwande Careers isn't a job board — it's a paid membership service. Jobseekers needed one place to subscribe, submit their intake form and pay, and have that submission land reliably in a central admin workflow instead of relying on manual, ad-hoc processes. Employers needed a separate channel to submit hiring requests through the same platform.

TESTING AND DEPLOYMENT

GitHub Actions workflow

The workflow runs on pushes to all branches and pull requests targeting main. Its test job uses Ubuntu, Python 3.11 and an in-memory SQLite database, installs requirements.txt and runs pytest tests/ -v. The deployment job depends on test success and triggers the Render deploy hook only when the branch reference is main.

This YAML defines the pipeline; it is not a pipeline execution log. The separately supplied backend report was generated by run_tests.ps1 and records 30 passing checks in 60.66 seconds. The workflow does not include a step to generate or upload that HTML report.

DOWNLOAD WORKFLOW YAML →

OPEN BACKEND TEST REPORT →

name: Pipeline

on:
  push:
    branches: ["**"]
  pull_request:
    branches: [main]

jobs:
  test:
    name: Run Tests
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4.2.2

      - name: Set up Python
        uses: actions/setup-python@v5.6.0
        with:
          python-version: "3.11"

      - name: Install dependencies
        run: pip install -r requirements.txt

      - name: Run tests
        env:
          FLASK_ENV: testing
          DATABASE_URL: "sqlite:///:memory:"
          SECRET_KEY: test-secret-key
        run: pytest tests/ -v

  deploy:
    name: Deploy to Render
    runs-on: ubuntu-latest
    needs: test
    if: github.ref == 'refs/heads/main'

    steps:
      - name: Trigger Render Deploy
        run: |
          curl -X POST "${{ secrets.RENDER_DEPLOY_HOOK_URL }}"
