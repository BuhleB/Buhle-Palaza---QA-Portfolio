WHAT I TESTED

Submission and admin workflows

I worked on backend routes, SQLAlchemy persistence and administrative workflows. My QA focus was whether valid submissions reached the intended destination, invalid input was rejected, and access to admin functions and uploaded CVs was controlled.

  • Contact, enquiry and employer submissions; required fields and input validation.

DEFECT INVESTIGATION

A success message hid a missing database record

I investigated why CV uploads and notification emails appeared successful while the Talent Pipeline list stayed empty. I followed the submission through the backend and found the missing database-save step.

My investigation

    Fix and follow-up

    I added the database save before notifications. My project account records 16 recovered submissions and retests of four related form types. The original recovery log and defect-specific retest are not attached; the local follow-up below checks the current code separately.

    LOCAL REGRESSION FOLLOW-UP

    Check the saved record after the request ends

    A new assisted follow-up exercised the current Free Pipeline route with a temporary SQLite database and uploads folder. All three checks passed: a valid submission persisted, and missing-email and missing-CV submissions were rejected without creating records.

    The positive check opens a fresh database session after the response. In a separate copy of the code, replacing the commit with a flush still returned success but left no saved record; the check failed as expected.

    REPEATABILITY

    A test job before deployment

    The GitHub Actions workflow runs pytest tests/ -v with Python 3.11 and an in-memory SQLite database. Its dependent deployment job calls the Render deploy hook on the main branch after the test job succeeds.

    This configuration covers the four basic pytest checks. The separate PowerShell runner produced the 30-check HTML report; the workflow does not run that script or upload its report.

    View workflow YAML →
    View the workflow configuration
    name: Pipeline

on:
  push:
    branches: ["**"]
  pull_request:
    branches: [main]

jobs:
  test:
    name: Run Tests
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4.2.2

      - name: Set up Python
        uses: actions/setup-python@v5.6.0
        with:
          python-version: "3.11"

      - name: Install dependencies
        run: pip install -r requirements.txt

      - name: Run tests
        env:
          FLASK_ENV: testing
          DATABASE_URL: "sqlite:///:memory:"
          SECRET_KEY: test-secret-key
        run: pytest tests/ -v

  deploy:
    name: Deploy to Render
    runs-on: ubuntu-latest
    needs: test
    if: github.ref == 'refs/heads/main'

    steps:
      - name: Trigger Render Deploy
        run: |
          curl -X POST "${{ secrets.RENDER_DEPLOY_HOOK_URL }}"
